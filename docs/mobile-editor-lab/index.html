Mobile editor lab

Four candidate shells for editing a customer card on a phone, rendered at 390 × 844. Each is interactive — tap the Section rows, drag the sheet, step through the wizard. Nothing here is wired to the app; it exists to settle the shell decision before components/SectionEditor.tsx is touched. Full analysis in docs/MOBILE_EDITOR.md.

Recommended hybrid

Phase 0 — foundations that are needed whichever shell wins: 16 px inputs, 44 px targets, a TouchSensor for drag, dvh + visual-viewport handling, and moving the shell styles out of inline CSSProperties so a media query is even possible.

Phase 1 — ship B. Cheapest shell that makes phone editing possible, and a safety net.

Phase 2 — upgrade B's Sunting segment to C + D: the card stays behind the sheet at every detent, and the rail carries Kembali / Seterusnya so the customer walks the Sections without leaving the card. Bahagian shrinks to one ☰ icon — still there for jumping and drag-to-reorder, no longer the only way to change Section. This is the recommendation.

Phase 3 — the last step's Seterusnya becomes Terbitkan / payment, turning the stepper into the funnel; and tap-to-edit on the live card as a per-Section enhancement.
